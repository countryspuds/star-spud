# ADR-0006 모바일 앱은 네이티브(Swift/Kotlin), 웹 베타 후 착수

- 상태: 채택 (2026-09-02). **재검토 조건**: 웹 베타 이후 앱 착수 시점에 팀 규모·일정을 보고 다시 판단한다.

## 맥락
최종 목표는 웹 + 모바일 앱이다. 팀은 웹과 앱의 UI가 달라야 한다고 보며, 웹뷰 포장(Capacitor)은 원하지 않는다. 후보는 React Native, Flutter, 네이티브.

## 결정
iOS는 Swift, Android는 Kotlin으로 각각 네이티브 개발한다. 착수는 웹 베타 이후(Phase 3). 순서는 iOS 우선.

## 결과
- 앱 두 개를 따로 만드는 것이므로 2인 팀 기준 작업량이 가장 크다. 이 점을 알고 선택했으며, 착수 시점에 재검토한다.
- 백엔드 API는 처음부터 웹·앱 공용 계약으로 설계하고, 앱 착수 시 v1을 동결한다.
- 표시 규칙(핀 색상, 감자 등급·상태)은 서버가 결정해 내려준다. 클라이언트 세 벌에 로직을 중복하지 않기 위해서다.
- 카카오맵은 네이티브 SDK를 쓴다. 광공해 타일 오버레이는 각 SDK의 타일 레이어 기능으로 재구현한다.
- iOS 앱에 소셜 로그인이 있으면 Apple 로그인이 필수이므로 [ADR-0009](./0009-auth-oauth-jwt.md)의 제공자 목록에 포함했다.
