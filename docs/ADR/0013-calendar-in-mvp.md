# ADR-0013 천문 캘린더를 MVP에 포함, KASI API 연동을 앞당김

- 상태: 채택 (2026-11-01)

## 맥락
PRD 1.0은 이벤트를 "수동 등록 테이블 + 읽기 전용 목록"으로 MVP에 두고, 캘린더 뷰와 천문연구원 API는 Phase 2로 미뤘다. 디자인 과정에서 월별 캘린더(일별 출몰시각·달 조도·현상·촬영 적기 띠)가 서비스의 두 번째 핵심 가치("언제 가야 하는가")를 가장 직접 보여주는 화면으로 확인됐고, 프론트가 mock 데이터로 구현돼 머지됐다(PR #6). 필요한 KASI API 4종(출몰시각·월령·천문현상·특일)은 모두 공공데이터포털에서 무료로 제공되며 월 단위 호출량이 작다.

## 결정
- `/calendar`를 MVP에 포함한다. 데이터는 서버가 KASI API를 월 단위로 받아 캐시하고 `GET /api/v1/calendar?year&month`로 준다([specs/12](../../specs/12-calendar.md)).
- `events` 테이블은 유지하되 `source=kasi` 행을 KASI 천문현상 API에서 자동 적재한다. 감자 배고픔 판정(specs/04)의 `is_major` 이벤트는 이 테이블을 그대로 쓴다.
- 이벤트 **알림 설정**(event_alerts)은 여전히 Phase 2.

## 결과
- 2026-11 마일스톤에 "KASI 4종 연동 + 캘린더 API"가 추가된다. 수동 이벤트 등록 화면은 관리자 API만 남긴다.
- 은하수 출몰시각·달 조도는 API에 없어 서버 계산(ADR-0004의 JVM 천문 라이브러리 검토와 묶음).
