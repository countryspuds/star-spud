# 02. 관측 조건

- Phase: **MVP**
- 관련: [01 명소 지도](./01-spot-map.md) · [04 감자](./04-potato.md) · [ADR-0004 스케줄러](../docs/ADR/0004-no-celery-in-mvp.md)

## 목적
명소·날짜별로 "오늘 밤 별이 보이는가"를 하나의 판정과 그 근거 지표로 제공한다. 이 판정은 핀 색, 감자 알림, 추천 정렬의 공통 기준이다.

## 사용자 스토리
- 입문자로서 명소를 눌렀을 때 "좋음/보통/나쁨"과 그 이유 한 줄을 보고 싶다.
- 취미가로서 시각별 구름량, 달 출몰 시각, 천문박명 시각을 정확히 보고 싶다.

## 정의

### 관측 창
- 하루의 "밤"은 **그날 저녁 천문박명 종료 ~ 다음 날 새벽 천문박명 시작**이다. 서버가 계산한다(KASI 출몰시각 API 기준, 명소 좌표 보정은 JVM 천문 라이브러리 검토 중).
- 사용자에게는 날짜 D의 "밤"으로 표시한다. 예: 9월 2일 밤 = 9월 2일 20:xx ~ 9월 3일 04:xx.
- "오늘 밤"의 기준: 접속 시각이 새벽 4시 이전이면 진행 중인 밤(전날 날짜), 4시 이후면 그날 밤.

### 구름량
- 기상청 단기예보 `SKY`(하늘상태) 코드를 구름량 %로 매핑한다: 1 맑음 → 10, 3 구름많음 → 60, 4 흐림 → 95. (단기예보에 구름량 % 자체는 없다.)
- 관측 창 안의 예보 시각(3시간 간격)들의 **평균**을 대표값으로 쓴다. 상세에는 시각별 값도 보여준다.
- 강수 확률 `POP`이 60% 이상인 시각이 창 안에 하나라도 있으면 대표값을 95로 올린다.

### 달
- 관측 창 중간 시각의 달 조도(%)와 그날의 월출·월몰 시각을 계산한다.
- **달 통과 조건**: 조도 50% 이하 **또는** 월몰 시각이 관측 창 시작 후 2시간 이내 **또는** 월출 시각이 관측 창 종료 2시간 이내(즉 창의 대부분에 달이 없음).

### 판정
| 조건 | 판정 |
|---|---|
| 구름 ≤ 30 그리고 달 통과 | `good` |
| 구름 ≤ 60 그리고 달 통과, 또는 구름 ≤ 30 그리고 달 미통과 | `fair` |
| 그 외 | `bad` |
| 구름 스냅샷 없음 | `unknown` |

- 판정과 "이유 한 줄"(예: "맑지만 보름달이 밤새 떠 있어요")을 서버가 함께 내려준다.
- 임계값은 설정값(`CONDITION_CLOUD_GOOD=30`, `CONDITION_CLOUD_FAIR=60`, `CONDITION_MOON_MAX=50`)으로 두고 코드에 상수로 박지 않는다.

### 날짜 범위
- 오늘, 내일, 모레. 기상청 단기예보는 발표 시각에 따라 모레 밤 일부가 비어 있을 수 있다. 창 안 예보 시각의 절반 이상이 비면 `unknown`.

## 데이터 갱신 (스케줄)
- 매시 10분에 실행. 명소의 격자 (x, y)를 중복 제거해 기상청 단기예보를 호출한다.
- 격자별 응답을 관측 창 기준으로 집계해 `weather_snapshots(spot_id, target_date)`에 upsert. `fetched_at` 갱신.
- 실패한 격자는 건너뛰고 로그. 다음 주기에 재시도. 기존 스냅샷은 지우지 않는다.
- 호출 제한: 공공데이터포털 일일 트래픽 안에서 격자 수 × 24회가 되도록 격자 수를 모니터링한다.

## API
- `GET /api/v1/spots/{id}/conditions?date=` →
  ```json
  {
    "date": "2026-09-02",
    "window": {"start": "2026-09-02T20:14+09:00", "end": "2026-09-03T04:31+09:00"},
    "condition": "fair",
    "reason": "구름은 적지만 달이 밤새 떠 있어요",
    "cloud": {"avg": 20, "hourly": [{"at": "...", "pct": 10, "pop": 0}, ...], "fetched_at": "..."},
    "moon": {"illumination": 82, "rise": "...", "set": "...", "phase_name": "보름달"},
    "twilight": {"evening_end": "...", "morning_start": "..."}
  }
  ```
- 지도 핀 목록(`GET /spots`)에는 `condition`과 `reason`만 포함한다.

## 엣지 케이스
| 상황 | 동작 |
|---|---|
| 그날 월출 또는 월몰이 없는 날(달력상 존재) | 없는 값은 null. 판정은 조도와 존재하는 값만으로. 통과 규칙에서 null인 조건은 건너뛴다 |
| 달 조도 50% 이하이지만 관측 창 내내 떠 있음 | 통과(입문자 기준으로 반달 이하는 허용) |
| 여름 위도 고려: 천문박명이 짧아 관측 창이 5시간 미만 | 창이 짧더라도 그대로 계산. 상세에 창 길이 표시 |
| 기상청 API 장애가 6시간 이상 지속 | 판정은 마지막 스냅샷으로 유지. `fetched_at` 6시간 초과면 응답에 `stale: true`, UI는 "N시간 전 예보" |
| 기상청 API 장애가 24시간 이상 | `unknown` 처리 |
| 새 명소가 등록됐는데 다음 스케줄까지 스냅샷 없음 | 등록 직후 그 명소 하나만 즉시 갱신 시도(백그라운드). 실패하면 `unknown` |
| 격자 변환 결과가 기상청 격자 범위(1~149, 1~253) 밖 | 저장 거부. 명소 등록 400 `KMA_GRID_OUT_OF_RANGE` |
| 같은 격자를 여러 명소가 공유 | 호출 1회, 스냅샷은 명소마다 기록 |
| 자정 직후 접속 | "오늘 밤"은 어제 날짜의 진행 중인 밤. 날짜 선택지도 어제 밤 / 오늘 밤 / 내일 밤 |
| 모레 밤 예보가 절반 이상 비어 있음 | `unknown`, 이유 "예보가 아직 없어요" |
| 강수 확률 높음 + SKY 맑음(불일치) | POP 규칙이 우선, 구름 95 |
| 사용자 시간대가 KST가 아님 | 모든 계산·표시는 Asia/Seoul 고정 |
| 달 조도 계산 오류(KASI 응답 없음·계산 예외) | 달 정보 null, 판정은 구름만으로(`fair` 상한), 로그 |

## 완료 기준
- [ ] 판정 서비스 `condition/service/ConditionService`에 표의 4가지 판정과 달 통과 규칙 3가지 조합의 JUnit 테스트가 있다(최소 12케이스).
- [ ] 관측 창 계산이 서울 기준 하지·동지 날짜에 대해 알려진 값과 ±5분 안에 맞는 테스트가 있다.
- [ ] 기상청 격자 변환이 공식 예제 좌표(서울 60,127 등) 3개 이상과 일치하는 테스트가 있다.
- [ ] SKY·POP → 구름량 매핑 테스트.
- [ ] 스케줄러가 1시간마다 돌고, 로컬에서 30곳 갱신이 1분 안에 끝난다.
- [ ] `stale`, `unknown` 상태가 UI에 문구로 드러난다.
- [ ] 임계값이 환경 변수로 바뀌면 판정이 따라 바뀐다.
